# Data dictionary — field-level specification

All employee and compensation records generated by this project are synthetic. IDs are immutable strings; dates are ISO-8601 `YYYY-MM-DD`. CSV exports use UTF-8. Monetary values are decimal numeric values (two decimal places where exported).

## Employee

| Field | Type | Required | Allowed values / units | Unique | Validation |
|---|---|---:|---|---:|---|
| id | string | Yes | `EMP-000001` pattern | Yes (PK) | Immutable; zero-padded six-digit counter |
| name | string | Yes | Synthetic display name | No | Non-empty |
| role_id | string | Yes | Existing Role.id | No | FK to Role |
| level_id | string | Yes | Existing Level.id | No | FK to Level |
| location_id | string | Yes | Existing Location.id | No | FK to Location |
| hire_date | date | Yes | Calendar date | No | Not after current snapshot date |
| employment_status | enum/string | Yes | ACTIVE, INACTIVE | No | Must be a supported lifecycle state |
| fte | decimal | Yes | (0, 1] | No | Contracted full-time-equivalent fraction |

## Role

| Field | Type | Required | Allowed values / units | Unique | Validation |
|---|---|---:|---|---:|---|
| id | string | Yes | `ROLE-01` etc. | Yes (PK) | Immutable |
| name | string | Yes | Job title | Yes | Non-empty, unique title |
| family | string | Yes | Engineering, People, Analytics, etc. | No | Non-empty job family |

## Level

| Field | Type | Required | Allowed values / units | Unique | Validation |

## Location

| Field | Type | Required | Allowed values / units | Unique | Validation |
|---|---|---:|---|---:|---|
| id | string | Yes | `LOC-BLR` etc. | Yes (PK) | Immutable |
| name | string | Yes | City/market label | Yes | Unique location name |
| country | string | Yes | ISO-like country code | No | Non-empty |
| currency | string | Yes | ISO 4217 code (INR, GBP, USD) | No | Must have a configured FX conversion |
| fx_to_inr | decimal | Yes | INR per one currency unit | No | Greater than zero; effective-date FX table recommended for production |

## CompensationBand

| Field | Type | Required | Allowed values / units | Unique | Validation |
|---|---|---:|---|---:|---|
| id | string | Yes | `BAND-<role>-<level>-<location>-2026` | Yes (PK) | Deterministic and immutable |
| role_id | string | Yes | Role.id | No | FK to Role |
| level_id | string | Yes | Level.id | No | FK to Level |
| location_id | string | Yes | Location.id | No | FK to Location |
| currency | string | Yes | ISO 4217 | No | Display/source currency; band amounts are normalized INR |
| minimum | decimal | Yes | INR/year at 1.0 FTE | No | Non-negative and <= midpoint |
| midpoint | decimal | Yes | INR/year at 1.0 FTE | No | Between minimum and maximum |
| maximum | decimal | Yes | INR/year at 1.0 FTE | No | >= midpoint |
| effective_from | date | Yes | Calendar date | No | <= effective_to when effective_to exists |
| effective_to | date/null | No | Calendar date or open-ended | No | Must not precede effective_from |

## SalaryRecord

| Field | Type | Required | Allowed values / units | Unique | Validation |
|---|---|---:|---|---:|---|
| id | string | Yes | `SAL-<employee-id>-YYYY-01` | Yes (PK) | Deterministic; immutable |
| employee_id | string | Yes | Employee.id | No | FK to Employee |
| effective_date | date | Yes | Calendar date | No | Must not precede hire date |
| base_salary | decimal | Yes | Annual gross base pay in `currency` | No | >= 0 |
| currency | string | Yes | ISO 4217 | No | FX must exist for effective date |
| fte | decimal | Yes | (0, 1] | No | FTE applicable to this salary record, not merely current employee FTE |
| annualized_inr | decimal/null | No when FX unavailable | INR/year at 1.0 FTE | No | Derived as base_salary * FX_to_INR / FTE; null when FX unavailable |
| band_id | string/null | No | CompensationBand.id | No | FK; may be null if no effective band is available |
| change_reason | enum/string | Yes | INITIAL, ANNUAL_REVIEW, PROMOTION, PART_TIME_CHANGE, CURRENCY_CHANGE | No | Must describe the change event |
| issue_type | string | No | Empty or labelled anomaly type | No | Used to label intentional test fixtures; never infer labels from salary alone |

## Relationships and cardinality

- Role 1:N Employee; Level 1:N Employee; Location 1:N Employee.
- Role + Level + Location 1:N CompensationBand (effective-dated band versions).
- Employee 1:N SalaryRecord, PerformanceEvidence, Tenure snapshots, Promotion, AdjustmentProposal.
- CompensationBand 0..1:N SalaryRecord; band link is optional when no valid band exists.
- ComparableGroup N:M Employee through `ComparableGroupMember` (bridge table, composite primary key).
- AuditEvent stores append-only polymorphic references to state changes (entity_type + entity_id); each proposal can have multiple events.

## Derived calculations

- `normalized_salary_inr = base_salary * FX_to_INR / FTE`.
- `compa_ratio = normalized_salary_inr / band_midpoint_inr`.
- `band_position = (normalized_salary_inr - band_min_inr) / (band_max_inr - band_min_inr)`.
- `tenure_years = (as_of_date - hire_date).days / 365.25`.

## Synthetic generation profile

Default seed: `20261022`. Default volume: 5,000 employees; 20 roles x 10 levels = 200 role/level combinations; five locations; three annual salary snapshots (2024–2026). The generator includes synthetic part-time changes, selected currency changes, promotions, performance evidence and labelled low-pay outliers. The `ground_truth` and `negative_scenarios` files are separate evaluation artefacts and must not be included in model input features.
